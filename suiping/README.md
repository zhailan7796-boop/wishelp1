# 随屏 · TaskbarFollow

**0.3.8 · Windows 11 x64 便携版**

从哪块屏幕的任务栏打开或恢复应用，就尝试让窗口在那块屏幕显示。
64 位应用优先使用 **C++ 窗口钩子在创建、恢复显示前定位**。所有已核验的任务栏窗口均有有限时的显示后补充检查。桌面、资源管理器、菜单及应用窗口内点击打开的独立窗口也尝试跟随点击屏幕。可选的「链接随屏」让应用里点开的网页也在点击的屏幕打开。

## 下载与使用

当前源码版本为 0.3.8。已发布的便携版仍可下载 [v0.3.7](https://github.com/zhailan7796-boop/wishelp1/releases/tag/suiping-v0.3.7)。如需打包当前源码，运行 build.ps1。

1. 解压整个 `TaskbarFollow-0.3.8-portable.zip` 文件夹，再双击 **Start.exe**。运行时已随包附带，无需安装 AutoHotkey 或使用管理员权限。
2. 等待状态显示 **运行中**，再从目标屏幕的任务栏打开或恢复应用。出现分组预览时，选择要跟随的窗口。
3. 点击「暂停跟随」或按 `Ctrl+Alt+F12` 切换启用状态。点右上角 × 或「收起到托盘」会继续后台运行，点「退出程序」可停止随屏。
4. 「查看日志」和「兼容性诊断」可用于排查特定应用。悬停预览默认启用，可在托盘菜单中切换。「连接第二块屏幕时自动启动」可在托盘菜单中按需开启。
5. 想让飞书等应用里点开的网页也出现在点击的屏幕：托盘菜单 →「应用里打开的链接也随屏…」，按提示做两步（见下方「链接随屏」）。

## 链接随屏（可选，默认关闭）

**解决什么：** 在屏幕2的飞书里点一个云文档，Chrome 会把它塞进自己最后用过的窗口——往往在屏幕1，只能手动把标签拖出来再拖到屏幕2。

**怎么做到的：** Windows 规定“链接交给哪个程序打开”只能由你在设置里选。随屏登记一个叫「随屏链接」的小程序（`LinkOpen.ahk`），你在 Windows 设置里把它设成默认浏览器。之后每次有应用打开网页：

- 「随屏链接」看你刚才点击的是哪块屏幕；
- 那块屏幕上已有 Chrome 窗口 → 链接开成那个窗口的新标签；
- 没有 → 在那块屏幕新开一个 Chrome 窗口（随屏运行时，窗口直接出现在那块屏幕）；
- 真正打开网页的始终是原来的浏览器（设置时自动记下，例如 Chrome），Chrome 本身不做任何改动。

**开启：** 托盘菜单 →「应用里打开的链接也随屏…」→ 确定。随屏会登记「随屏链接」并打开 Windows 设置，在「随屏链接」页面点顶部的「设为默认值」（或把 HTTP、HTTPS 两项都改成「随屏链接」）。开启后菜单项前会打勾。

**撤销：** 任选一种——托盘菜单再点这一项选「是」；或双击文件夹里的 **撤销链接随屏.cmd**；或直接在 Windows 设置 → 应用 → 默认应用 → Google Chrome → 「设为默认值」。随屏只写当前用户注册表的三处（`HKCU\Software\Classes\TaskbarFollow.Link`、`HKCU\Software\Clients\StartMenuInternet\TaskbarFollow.Link`、`HKCU\Software\RegisteredApplications` 里的 `TaskbarFollow.Link`），撤销会删除它们。

**注意：** 开启后 Chrome 可能提示“不是默认浏览器”，点关闭即可（打开网页的仍然是 Chrome）。移动或删除随屏文件夹前请先撤销，否则 Windows 找不到「随屏链接」时会请你重新选择浏览器。链接内容不写入日志；`logs\LinkOpen.log` 只记录“开成标签 / 新窗口”、目标屏幕和浏览器名称。

## 撤销与回滚

改动前的全部源文件、配置、`Start.exe` 和原生组件指向（`native\bin\runtime.ini`）备份在 `backup\2026-11-20-before-link-follow\`，里面的「恢复说明.md」写了逐步恢复方法。原来的原生组件 `NativeHooks-00ef0faee19e-x64.dll` 仍在 `native\bin\`，从未被覆盖。

## 版本记录

### 2026-11-23 傍晚：芒果TV 播放窗口“闪一下就没了”

- **现象：** 14:00 用一键生效后，飞书链接已正常；芒果TV 点剧后播放窗口闪一下就消失。日志为 `app launch requested` 紧接着 `app launch window-changed`（同一秒）。
- **原因：** 补充定位移动已显示的窗口时，原来一律先把窗口最小化，再改到目标屏、再还原（为了让 Chrome 等应用在新屏幕重新绘制）。芒果TV 的播放窗口一被最小化就把自己隐藏起来；随屏看到窗口隐藏，就停止了，不再还原。播放窗口没有任务栏按钮，于是用户也找不回来。
- **修改：** 没有自己任务栏按钮的窗口（工具窗口、被其他窗口拥有的窗口，例如芒果TV 播放窗口）改为直接平移到点击的屏幕（`SetWindowPos`，不激活、不改层级），**绝不最小化**；最大化的这类窗口在目标屏先还原、到位后再最大化。有任务栏按钮的普通窗口（Chrome、飞书等）流程不变。代码在 `lib\Native.ahk` 的 `WindowMoveOperation`（新参数 `direct`、`NoTaskbarButton`）和 `lib\NativeEngine.ahk` 的 `CompatibilityMove`。
- **测试：** `tests\AppLaunchToolWindow.ahk` 增加两个播放窗口：一个“最小化就隐藏自己”（旧代码下得到与 14:00 完全相同的 `requested` → `window-changed`），一个在单独的 32 位进程里（新增 `tests\PlayerFixture.ahk`，和 芒果TV.exe 一样跨进程）。所有播放窗口都要求“全程没被最小化”。`tests\WindowMove.ahk` 增加直接平移的普通/最大化用例。
- 改动前文件备份在 `backup\2026-11-23-before-no-minimize\`（含恢复说明）。

### 2026-11-23：芒果TV 播放窗口、链接随屏开启入口

- **芒果TV 播放窗口：** 日志确认播放窗口是 Qt 的“工具窗口”（类名 `Qt5QWindowToolSaveBits`，带工具窗口样式，并由芒果TV 自己的另一个窗口拥有），旧规则把这类窗口一律当成菜单/浮层跳过。现在仅对“应用内点击后新出现的前台窗口”放宽：同一程序的工具样式窗口、被同一程序的其他窗口拥有的窗口也可以跟随；菜单、提示框、不可激活的浮层、隐藏或过小（小于 240×160）的窗口、全屏窗口仍然不动。任务栏点击的规则不变。
- **工具窗口坐标：** 移动工具样式窗口时按屏幕坐标计算位置（Windows 对这类窗口的放置坐标规则不同）。
- **诊断：** `app launch unmatched-window` 日志行增加窗口样式、尺寸、所在屏幕、拥有者进程和具体拒绝原因。
- **开启「链接随屏」更方便：** 新增 **开启链接随屏.cmd**；`更新原生组件.cmd` 的最后一步也会检查默认浏览器，未开启时直接问你要不要开启。
- **自检：** `更新原生组件.cmd` 现在还会检查随屏主程序能否加载、跑工具窗口识别（`tests\LaunchedWindow.ahk`）和跨屏移动（`tests\WindowMove.ahk`）；主程序检查不通过时不会重启随屏。
- 改动前文件备份在 `backup\2026-11-23-before-tool-window-fix\`（含恢复说明）。

### 2026-11-20：应用内新窗口与应用里打开的链接（0.3.8）

- **应用内新窗口（如芒果TV 点剧集弹出的播放窗口）：** 以前只接受“与被点击窗口同一个进程”的新窗口。芒果TV 这类多进程软件的新窗口常来自自己的另一个进程，所以被当成无关窗口跳过，留在屏幕1。现在也接受：同一个程序文件（同一个 exe，排除浏览器、AutoHotkey、系统目录等公共宿主）或被点击程序启动的子进程的新窗口。仍然只在点击后有限时间内、只对“点击前不存在的新前台窗口”生效。
- **等待时间：** 应用内点击后的等待从 2 秒延长到 5 秒（需要重新编译原生组件，见下方）。等待期间不再挡住任务栏悬停预览。
- **窗口很多时不再失效：** 桌面可见窗口超过 32 个时，旧版会直接放弃这次应用内点击；现在优先记录被点击程序自己的窗口。
- **诊断：** 应用内点击后出现了新窗口却没有跟随时，日志会写一行 `app launch unmatched-window`，带原因、进程路径、窗口类名（不含标题），方便下次定位。
- **链接随屏：** 新增上面的「随屏链接」。随屏运行且原生组件为新版时，新浏览器窗口在创建时就放到点击的屏幕；否则由「随屏链接」在窗口出现后移过去（会先在原屏闪一下）。

**让原生部分生效（一次）：** 双击随屏文件夹里的 **更新原生组件.cmd**（2026-11-23 新增）。它先做几项只读自检（「随屏链接」脚本能否加载、链接命令行、跟随判断），再备份 `native\bin\runtime.ini`、编译原生组件并在独立的测试桌面上跑原生自测；任何一步失败都会自动改回原来的组件，什么都不变。全部通过后会问你是否立即重启随屏。记录保存在 `logs\update-native-时间.txt`。
也可以手动：在随屏文件夹里打开 PowerShell，运行 `powershell -NoProfile -ExecutionPolicy Bypass -File native\build-native.ps1`，看到 `PASS native hook build` 后，从托盘「退出」随屏，再双击 Start.exe。不编译也能用：芒果TV 的多进程窗口识别和「随屏链接」照常工作，只是应用内等待仍为 2 秒、浏览器新窗口改为出现后再移动。

### 2026-11-18：启动缓存、任务栏和应用内打开窗口

原生鼠标钩子在按下时读取事件自带的物理坐标，并固定本次操作的目标屏幕。随屏启动时保留首批任务栏数据，应用身份加载完成后立即发布。一块任务栏只漏扫一次且位置相同时，保留它上一轮的按钮数据。显示配置变化及 UIA 重连会重新请求当前任务栏数据。

任务栏右键菜单中可核验的冷启动使用同一套显示前定位。任务栏窗口候选刚发生变化时，显示后定位可用准确 AppID 核验新激活的窗口。应用内点击也能关联随后显示的独立窗口，要求能与点击来源核验，普通焦点切换仍由 Windows 处理。

### 2026-11-17：共用 DPI 坐标与异步恢复修复

修复所有应用共用的两处问题：任务栏输入回调、事务读取和窗口钩子现在都在短暂的物理坐标上下文中计算位置；调用应用原窗口过程前恢复它自己的 DPI 上下文。此前只在线程启动时设置缩放感知，回调仍可能使用系统缩放坐标，导致副屏点击漏判或有效目标屏被拒绝。

显示后补充定位改为按实际状态推进：确认已最小化、确认目标还原位置、再恢复原来的普通或最大化状态。跨进程异步 API 返回成功不再被当作前一步已经完成。每阶段只提交一次，由原有计时器推进；每步重新核对同一点击、窗口身份及屏幕，新输入、暂停和超时会停止后续操作。

本机真实任务栏已通过飞书、Chrome、资源管理器、随屏状态窗口的双向回归，以及双窗口分组预览。另有 64/32 位自有跨进程窗口、不同 DPI 上下文及原生首次绘制回归。腾讯视频本轮未找到可用任务栏按钮，没有计为真实应用验收通过。具体证据见[测试报告](docs/TEST-REPORT.md)。生产定位逻辑没有新增应用名称分支。

### 状态界面按需刷新

隐藏或最小化状态窗口时停止界面时钟，不查询显示器、不格式化页面文本、不写控件；后台任务栏识别、原生定位及健康检查照常运行。重新显示或从系统恢复窗口时立即补齐最新状态。可见时只有发生变化的文字/颜色才写入控件，运行时间每秒更新。

原生引擎的 200ms 状态轮询保留，但稳定不变的轮询不再触发界面刷新；这不是通过降低定位检查频率来节省资源。本次不修改原生 DLL、任务栏缓存和窗口移动路径。

### 原生缓存身份解析去重

每轮缓存发布先按精确 AppID、完整路径和进程名建立窗口索引，同一 AppID 在多块屏幕上只解析一次候选窗口及冷启动资格。各任务栏按钮仍单独保存句柄和物理坐标；路径规范化、文件资格检查和共享宿主索引也在本轮复用，下一轮重新核验。

保留显式 AppID 不匹配时禁止路径回退、候选顺序、32 个候选上限及全部匹配窗口的路径冲突检查。新增等价性回归与解析微基准；测量结果仅代表缓存解析步骤，不等于整机 CPU、内存或首帧响应的改善幅度。

### UIA 筛选与批量矩形缓存

原生辅助进程在 UIA 查询时直接筛选任务栏应用按钮，只批量缓存 AppID 和物理矩形，不再逐按钮读取当前矩形，也不为正常扫描获取名称和类名。诊断扫描仍可按需取得完整字段；悬停和兼容模式命中使用独立缓存。

每约 750ms 重新获取一次快照，不沿用上一轮元素或坐标。新增跨进程自有窗口测试，核对窗口移动、缩放后坐标更新；实际双任务栏另做识别等价性与扫描耗时对照，结果见 [测试报告](docs/TEST-REPORT.md)。

### 退出清理加固

原生停止接口现在明确返回完成结果。只有确认工作线程退出、钩子清理完成后，才释放共享映射和 DLL；超时或卸钩失败时保留必要资源、记录原因并允许重试，其他退出清理继续执行。启动失败也按同样规则回滚，建消息队列前收到的停止请求不会丢失。

工作线程持有独立 DLL 引用，避免调用者提前卸载仍在执行的代码。正常停止会释放该引用；退出不完整时保留到成功重试或整个进程结束，不会强制终止工作线程。

### 连接第二块屏幕时自动启动

开启屏幕连接检测后，进入 Windows 桌面时，单屏只运行轻量检测器。Windows 识别到两块可用屏幕并稳定后，再后台启动完整随屏。开机时双屏已经接好，以及之后再接外屏，都能触发检测。检测通知合并处理，另有 2 秒低频检查兜底。

随屏已经运行时，检测器不重复启动、不弹出状态窗口。手动退出后，同一次连接不会反复拉起；断开至单屏、再接入双屏可再次触发。拔掉外屏不会强制结束已经运行的随屏。可在新版托盘菜单“连接第二块屏幕时自动启动”中关闭，或运行 `tools/Configure-DisplayStartup.ahk disable`。

启用时为当前用户注册 Windows 登录任务，运行 `DisplayWatch.ahk`。从旧版升级后，可关闭再开启该开关，将旧的随屏启动快捷方式迁移为登录任务。便携包默认由用户手动启动。

### 资源管理器、32 位应用与状态窗口跟随

资源管理器的默认身份解析为 Windows 系统目录中的 `explorer.exe`，没有文件夹窗口时也能取得可核验路径。对同一进程复用的隐藏窗口，显示或恢复时重新核对身份；已有可见窗口仍按缓存中的 HWND/PID 选择。

32 位应用（本机腾讯视频属于此类）在选中窗口显示并稳定后尝试一次兼容移动，并核对目标屏幕。本机腾讯视频的固定路径按钮与运行身份 `TencentVideo.QQLive.v1` 已用显式完整路径别名关联。新输入、暂停、关闭或超时会取消等待；不承诺它的第一帧已经位于目标屏幕。

随屏状态窗口使用独立应用身份。收到自己任务栏按钮的明确点击后，只预置目标几何或最小化还原位置，显示和恢复仍交给 Windows；隐藏窗口不自行弹出。

已显示窗口的跨屏唤起统一在系统激活结束后，短暂最小化、更新目标还原位置，再恢复原来的普通或最大化状态，让应用在目标屏重新建立画面。此流程按窗口状态处理，不使用 Chrome 或其他软件名称分支。

所有已核验的任务栏身份都有显示后补充检查，包括已有窗口的应用包和拥有准确 HWND/PID/AppID 的系统托管窗口。已有窗口核对缓存中的句柄与进程，或用实时准确 AppID 核对刚激活的窗口。冷启动要求准确路径及必要的应用身份。原生处理已绑定时先等待它完成，其后最多执行一次分阶段补充定位，每一步确认系统状态后才继续。

桌面快捷方式、资源管理器和菜单的明确左键释放会建立最长两秒的打开意图。只接受随后显示的另一个独立前台窗口，排除点击来源和点击前已有的前台窗口。应用内点击还会核对新窗口与来源的关系，以及点击时已有的窗口。新输入会取消此前的等待。

悬停时核对当前缩略图的实际标题与本轮任务栏窗口缓存；单个候选也不免除标题核验，标题重复时跳过自定义预览，避免显示上一次悬停的软件。

## 这版改变了什么

| 操作 | 原生模式处理 |
| --- | --- |
| 冷启动具有已核验路径的 64 位桌面应用（含 CCSwitch、Edge / VS Code） | 根据完整路径参与，不再按应用名称白名单限制；在窗口创建阶段指定目标屏，并在首次显示前处理应用重新应用旧位置的请求；共享程序路径的多身份需精确 AppID |
| 冷启动 Edge PWA（如 DeepSeek） | 从快捷方式读取独立 AppID 和启动器信息，待窗口设置精确身份后，在首次显示前定位；不按同一个 msedge.exe 混同所有应用 |
| 悬停窗口缩略图 | 用独立 DWM 预览层在当前屏幕显示对应画面；移开、点击或按键后关闭，原窗口不移动、不恢复、不抢焦点 |
| 64 位应用从最小化恢复 | 在应用自己的窗口线程中预备目标位置，保留普通/最大化状态，再由 Windows 正常显示 |
| 唤起已经可见的 64 位窗口 | 激活完成后通过最小化、目标位置更新、恢复来重新建立画面，保留普通/最大化状态 |
| 已核验的 32 位应用 | 有限等待所选窗口显示、稳定后做一次兼容定位，确认实际目标后再计成功 |
| 随屏自己的状态窗口 | 明确任务栏点击后预置目标几何或还原位置，保留 Windows 的显示/最小化行为 |
| 点击分组预览 | 通过 Windows 实际激活/恢复的 HWND、PID 及任务栏应用身份核验所选窗口 |
| 点击预览关闭按钮 | 观察关闭消息，取消尚未完成的定位，避免把关闭当作选择 |
| 桌面、资源管理器、菜单打开新窗口 | 最长两秒等待另一独立前台窗口，在点击屏幕补充定位 |
| 应用内部点击打开独立窗口 | 对照点击时已显示的窗口及点击来源，核验随后 5 秒内新显示的前台窗口；同进程、同一程序文件（非公共宿主）或其子进程的窗口均可跟随 |
| 应用里打开网页链接（需开启「链接随屏」） | 点击的屏幕已有浏览器窗口 → 开成新标签；没有 → 新浏览器窗口在创建时放到点击的屏幕 |
| 同屏点击、修饰键点击 | 保留系统行为 |
| 新输入、暂停、显示配置变化、超时 | 取消待处理定位；超时会显示反馈 |

任务栏应用身份与几何位置由独立 UIA 进程提前缓存；原生输入线程在真实鼠标事件里记录物理坐标和目标屏幕。输入回调不执行 UIA、读快捷方式、文件日志或等待应用响应。

## 试用范围

- 当前原生钩子为 **64 位**。具有已核验完整路径的桌面应用和已识别 Edge PWA 可参与冷启动定位；已有窗口通过精确 HWND/PID 关联处理普通/最大化恢复及多窗口选择。参与识别不等于该真实应用已完成兼容性验收。
- 32 位应用采用显示后兼容路线，实际应用仍需验收；没有 32 位显示前注入组件。缓存未就绪、应用身份不明、权限更高的应用、独占/无边框全屏、非独立对话框，不保证处理。普通权限工具不自动提权。
- 原生任务栏被其他窗口遮挡时，命中检查不会把覆盖窗口上的点击当作任务栏点击。自动回归遇到遮挡会停止。
- 冷启动应用也可能在首次显示后再次自行移动。本版完成首次显示后结束定位，不持续钉住窗口，因此仍需真实应用验收，不能承诺所有应用从每一帧起都完全一致。
- Windows 11 的任务栏 UIA peer 和 AppID 不是跨所有系统更新稳定的任务栏协议；缓存过期时会暂停识别并重连。
- 本机双屏混合缩放已回归；其他 DPI 组合、贴靠分组和自定义布局仍需实际检查。原生测试窗口通过不等于所有应用都已兼容。
- 悬停预览保持画面比例，由 Windows 合成源窗口当前可提供的内容；最小化应用可能显示其保留画面。它在当前屏增加预览层，系统 Peek 在原屏的效果仍由 Windows 控制。标题重复、无障碍信息不足等多窗口歧义场景会跳过自定义预览，保留系统行为。

## 配置与回退

修改 `settings.ini` 后退出并重新启动：

```ini
[General]
Enabled=1
Engine=native
FollowPeek=1
BringActiveAcrossMonitors=1
ActivationTimeoutMs=8000
StableDelayMs=180
```

`Engine=native` 为本版默认；`Engine=compatibility` 可手动切回 0.1.x 的激活后迁移方式。`StableDelayMs` 只用于兼容模式。原生模式的冷启动等待由 `ActivationTimeoutMs` 控制，预览选择的定位窗口约为 1.8 秒；开始其他操作会取消本次等待。

应用映射仍使用 `[AppIdMap]`，完整路径优先。原生冷启动需要核验真实可执行文件路径，来源为精确配置、无歧义快捷方式、App Paths 注册项或已核验窗口的进程路径，不猜测安装目录。

同一程序确有两个等价任务栏身份时，可在 `[AppIdAlias]` 配置 `精确AppID=准确exe完整路径`。只接受存在的 Windows 可执行文件；值不能是另一别名。它明确关联这两个指定身份，窗口实际路径也必须相同。其他不同身份、共享宿主及其他安装路径仍单独核验；移动程序目录后需更新本机配置。

Edge PWA 的有参数快捷方式单独识别，不会作为普通进程名映射。其 AppID 在窗口创建后才设置时，会等待精确身份匹配再修改显示前几何，避免误带走普通 Edge 或其他 PWA。`FollowPeek=0` 可关闭新增的悬停预览。

「链接随屏」的设置在 `[LinkFollow]`：`Browser`、`BrowserArgs` 是开启时自动记下的原浏览器及其参数（不要填成随屏自己的程序）；`Enabled=0` 时「随屏链接」只是原样转交给浏览器；`ReuseScreenWindow=0` 表示即使点击的屏幕已有浏览器窗口，也总是新开窗口。这几项改完立即生效，不用重启随屏。

## 原生组件与源码

`native/NativeHooks.cpp` 使用 Windows `WH_CBT`、观察关闭及隐藏窗口显示消息的 `WH_CALLWNDPROC`，以及临时窗口子类处理显示前几何。Windows 会将钩子 DLL 加载到同一桌面的相关 64 位进程中；只有明确点击并核验身份的目标窗口才参与定位。

退出先禁用定位并取消事务，确认线程与钩子清理完成后再释放控制器资源；超时会记录未完成的清理并保留必要引用到重试或进程结束。实际挂接过临时窗口子类的应用会保留 DLL 映射直到该应用退出，以保证回调地址安全；子类在首次显示、取消或超时后移除。DLL 以源码内容摘要命名，更新不覆盖应用仍在使用的文件。无需为了更新而强制关闭应用。

构建需要 Visual C++ x64 和 Windows SDK，使用 `build.ps1`。便携包中的 `settings.ini` 来自 `settings.default.ini`。构建时如果缺少本地设置文件，会复制一份默认设置供测试使用。

`native/build-native.ps1` 编译并运行四组原生测试：`NativeLifecycleTests`、`NativeRoutingTests`、`NativePaintTests`、`NativeTests`；也可分别运行 `native/bin` 中对应的可执行文件，传入当前 DLL 路径。某些自动化沙箱会阻止跨进程钩子加载；不能把这种环境中的未执行当作测试通过，应在普通用户环境复核。

运行原生测试不需要管理员。测试会创建独立 Windows 桌面，只操作测试进程自己的窗口。
