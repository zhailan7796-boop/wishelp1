## 少一次把窗口拖回来的动作

主屏上开着文档，你在副屏的任务栏点开浏览器，窗口却盖到了文档上。随屏会尝试让打开或恢复的应用窗口出现在你点击任务栏的那块屏幕，少一次来回拖拽。

- **先看一眼再打开。** 悬停在任务栏的窗口缩略图上，可以在当前屏幕预览，原窗口留在原位。
- **想暂停就暂停。** 按 `Ctrl+Alt+F12` 切换跟随状态，也可以从托盘打开状态窗口操作。
- **接上副屏再启动。** 可在托盘菜单开启「连接第二块屏幕时自动启动」。

## 0.3.7 更新

桌面、资源管理器和菜单点击打开的独立窗口，也会尝试跟随点击屏幕。悬停预览会核对当前窗口，避免显示上一应用的画面。

17 组脚本检查和 4 组原生回归通过，覆盖跨屏恢复、原状态保留、实际绘制和取消操作。具体应用仍受窗口身份、权限和启动方式影响，详见[验证记录](docs/TEST-REPORT.md)。

## 2026-11-17：共用定位修复

修复任务栏输入、事务读取和窗口钩子的 DPI 坐标上下文，解决混合缩放时副屏点击漏判、有效目标屏被拒绝的问题。显示后补充定位按真实窗口状态分阶段推进，避免跨进程异步最小化尚未完成就恢复；保留普通或最大化状态，并在新输入、暂停或超时时取消。

生产定位逻辑没有新增应用名称分支。本机真实任务栏已通过飞书、Chrome、资源管理器和随屏状态窗口的双向回归，以及双窗口分组预览；腾讯视频本轮未找到可用按钮，未计为真实应用验收通过。64/32 位跨进程窗口和 DPI 回归、17 组脚本检查及 4 组原生测试已通过。详见[验证记录](docs/TEST-REPORT.md)。

新增只读诊断工具 `tools/Inspect-NativeState.ps1`，用于核对实际加载组件、后台心跳和任务栏缓存。

## 三步开始

1. 下载便携 ZIP，完整解压到任意文件夹。
2. 双击 `Start.exe`，等状态显示「运行中」。运行时随包附带。
3. 把一个应用最小化，再从另一块屏幕的任务栏点它，看看窗口出现在哪块屏幕。

遇到问题可以从状态窗口打开「兼容性诊断」，再到 [Issues](https://github.com/zhailan7796-boop/wishelp1/issues) 反馈系统版本、应用名称和复现步骤。

## 源码与构建

程序入口为 [TaskbarFollow.ahk](TaskbarFollow.ahk)。[lib/](lib) 包含状态窗口和应用识别代码，[native/](native) 包含 Windows 窗口定位组件，[tests/](tests) 包含回归检查。

在 Windows 上安装 Visual C++ x64 工具和 Windows SDK 后，运行 `build.ps1` 构建便携包。详见[原生定位设计](docs/NATIVE-ENGINE.md)、[项目许可证](LICENSE)和[第三方组件说明](THIRD-PARTY-NOTICES.md)。
